# AGENTS.md

## NestJS

This app's version of NestJS is likely newer than what you know. https://docs.nestjs.com/llms.txt indexes its documentation, with a markdown page per chapter.

The official NestJS agent skills are installed with `npx @nestjs/skills add --agent all`, which also updates them: the mistakes agents make in Nest apps, with recipes checked on the released packages. An agent loads a skill when a task matches it.

Nest has first-party packages for these, so check them before adding another library or writing your own:

- OpenAPI: [`@nestjs/swagger`](https://docs.nestjs.com/openapi/introduction.md). GraphQL: [`@nestjs/graphql`](https://docs.nestjs.com/graphql/quick-start.md). WebSockets: [`@nestjs/websockets`](https://docs.nestjs.com/websockets/gateways.md). Microservices: [`@nestjs/microservices`](https://docs.nestjs.com/microservices/basics.md).
- Sign-in: [`@nestjs/authentication`](https://docs.nestjs.com/security/authentication.md). Permissions: [`@nestjs/authorization`](https://docs.nestjs.com/security/authorization.md). Rate limiting: [`@nestjs/throttler`](https://docs.nestjs.com/security/rate-limiting.md).
- Configuration: [`@nestjs/config`](https://docs.nestjs.com/application/configuration.md). Caching: [`@nestjs/cache-manager`](https://docs.nestjs.com/data/caching.md). Health checks: [`@nestjs/terminus`](https://docs.nestjs.com/reliability/terminus.md). Events inside the app: [`@nestjs/event-emitter`](https://docs.nestjs.com/application/events.md).

Validation works with Zod, Valibot, ArkType or any other Standard Schema library, with no classes or decorator metadata: `StandardSchemaValidationPipe` with `@Body({ schema })` or `@Param('id', { schema })` (https://docs.nestjs.com/application/validation.md). `class-validator` still works, through `ValidationPipe`.

`NodeAdapter` from `@nestjs/platform-node` is the fastest HTTP adapter, ahead of Fastify (https://docs.nestjs.com/http/performance.md).

A route handler can return a web `Response`, a `ReadableStream` or an async generator, and Nest streams it as it's produced (https://docs.nestjs.com/http/streaming-responses.md).

Nest's packages are ESM only, and this project is ESM too: relative imports end in `.js`, `__dirname` doesn't exist (use `import.meta.dirname`), and tests run on Vitest, so mocks are `vi.fn()`, not `jest.fn()`.

In this project, `src/main.ts` creates the app, sets the global `/api` prefix and listens on `PORT` (3000 by default), and `src/app.module.ts` is the root module that imports the others. Data access is Prisma 7 (not a Nest package): the schema is `prisma/schema.prisma`, the client is generated into `src/generated/prisma` (git-ignored; Prisma 7 `migrate dev` does not regenerate it, so use `npm run db:migrate`, which also runs `prisma generate`), and `PrismaService` in `src/prisma` is injected globally. Types and Zod schemas shared with the frontend live in the `@novel/shared` workspace; request bodies are validated with `@Body({ schema })` via the global `StandardSchemaValidationPipe`. Every route under `/api/admin/*` is protected by the global `AdminAuthGuard` (cookie JWT) unless marked `@PublicAdmin()`; read the signed-in teacher with `@CurrentAdmin()`. Content admin (categories, vocabulary + CSV import, lessons, games) lives in `src/content`; the pure word-selection rule a game uses is `src/content/word-selection.ts`. The question bank (questions, passages, paste/CSV import) is `src/questions` (`/api/admin/questions`, `/api/admin/passages`); question schemas, the paste-text parser and the pure grading library (`gradeQuestion`, `normalizeAnswer`) live in `@novel/shared` with their unit tests, so the server and the teacher's preview grade the same way. Exams live in `src/exams`: teachers build them at `/api/admin/exams` (sections of bank questions, results and stats), students take them at `/api/play/exams` and `/api/play/attempts` (autosave per answer, server-held deadline with a 30-second grace, overdue attempts are auto-submitted with what was saved, grading on the server with `gradeQuestion`; answers never reach the student before `showResult` allows). An attempt's shuffled question/option order is stored in `ExamAttempt.order`; responses are kept in the order the student saw and mapped back with `toOriginalResponse` before grading. Homework lives in `src/assignments` (`/api/admin/assignments`, students read `/api/play/assignments`): an `Assignment` is a Unit + game (with `minStars`) or an exam, for some classes (`AssignmentClass`) or `forAll`, with `dueAt`; progress is never stored but computed from `PlaySession` (only rounds finished since the assignment was created) and submitted `ExamAttempt`s by the pure `assignmentProgress` in `@novel/shared`. Classes (`/api/admin/classes`) and student accounts managed by the teacher live in `src/students` (`/api/admin/students`). Students sign in through `src/student-auth` (cookie `ng_student`); every route under `/api/play/*` is protected by the global `StudentAuthGuard` unless marked `@PublicPlay()`, and `@CurrentStudent()` reads the signed-in student. The play loop (start a round, finish it, history) is `src/play`; stars are computed on the server with `rateRound` from `@novel/shared`, and a round only accepts answers for the words it issued (`PlaySession.wordIds`). Uploads go through `src/media` (validated by file content, images re-encoded to WebP) into `UPLOAD_DIR`, served at `/uploads`. `src/media/remote-media.service.ts` finds pictures (Fluent Emoji from the bundled index `fluent-emoji-index.ts`; Pixabay only when `PIXABAY_API_KEY` is set) and pronunciations (dictionaryapi.dev + Wikimedia Commons MP3), always downloading into `UPLOAD_DIR` through `fetchRemote` (https + host allowlist + size limit + 429 retry); it takes an image id, never a URL. `scripts/seed-media.ts` fills seed words (needs internet; runs services without Nest DI because tsx emits no decorator metadata). Error responses carry a machine-readable `code` (helpers in `src/common/errors.ts`). E2E tests must leave real data as they found it; `vitest.config.e2e.ts` points `UPLOAD_DIR` at a temp folder. App-wide setup (prefix, cookies, pipes, static uploads) lives in `src/app.setup.ts` and is shared by `main.ts` and the e2e tests. The plan for the whole project is `../docs/PLAN.md`. Unit tests sit beside the code as `*.spec.ts` and the e2e test is in `test/`; Vitest runs them (`npm test`, `npm run test:e2e`).

When a task says how to test, follow it. When it says nothing, cover the behaviour you change with focused tests rather than adding broad e2e suites.
